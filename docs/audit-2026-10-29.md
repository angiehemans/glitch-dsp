# Audit, 29 October 2026

A whole-repo review, assuming one performer on one laptop on stage: a single user, but the audio must
never glitch and the app must never freeze mid-song. Items are ticked as they're fixed.

## Must fix

- [x] **1. Adding a song to the setlist stops the song that's playing** (`engine/src/bridge/WebUi.cpp`, setlist and song commands)
  - **Problem:** `loadSong()` reloads the *current* song, and loading stops playback. Adding a song to a setlist, selecting a setlist, or deleting any library song stopped the song mid-play.
  - **Fix:** refresh only the preload there; keep `loadSong()` for real song changes.

## Should fix

- [x] **2. Pressing play can freeze the app for seconds** (`engine/src/audio/BackingPlayer.cpp`, `play`)
  - **Problem:** waits up to 0.5 s per track for read-ahead, on the UI thread, holding the player's lock: up to 8 s for 16 tracks on a slow drive.
  - **Fix:** one shared 500 ms deadline, waited before taking the lock.
- [x] **3. The tests never run in CI** (`.github/workflows/build.yml`)
  - **Problem:** FadeTest, FootswitchTest, TunerTest and BackingTest are excluded from the build and CI never runs them.
  - **Fix:** build and run them in the Linux job.
- [x] **4. Every fader move sends the whole app state** (`engine/src/bridge/WebUi.cpp`, `sendState`)
  - **Problem:** each command rebuilds and sends the full state; a fader drag sends dozens a second, and each is parsed and re-rendered.
  - **Fix:** mark the state dirty and send it at most once per 30 Hz timer tick.
- [x] **5. settings.json can be corrupted by a crash** (`engine/src/project/ProjectStore.cpp`, `saveSettings`)
  - **Problem:** written in place; a crash mid-write loses the audio and MIDI setup.
  - **Fix:** the same temp-file-then-move write projects use (`writeJson`).
- [x] **6. No test for the project store** (`engine/src/project/ProjectStore.cpp`)
  - **Problem:** converting old projects, "preset modified", and the split-exit move rule have no test.
  - **Fix:** a ProjectStoreTest tool, run in CI.
- [x] **7. WebUi.cpp does every job** (`engine/src/bridge/WebUi.cpp`, ~2,060 lines)
  - **Problem:** chains, blocks, ABY, routing, presets, footswitch, tune, songs, setlists, windows, state and meters in one class.
  - **Fix:** move songs, setlists and the track mix into their own class, and the footswitch mappings and actions into another.
- [x] **8. MIDI learn has no UI any more** (`WebUi.cpp`, `mockEngine.ts`, `commands.ts`, `model.ts`)
  - **Problem:** unused since the switch menus; its `learnedNow` special case sits in every footswitch press.
  - **Fix:** delete it.
- [x] **9. An old copy of ChainStrip is still in the repo** (`ui/glitch/components/ChainStripBackup/`)
  - **Problem:** nothing imports it; 1,189 lines.
  - **Fix:** delete the folder.

## Nice to have

- [x] **10. Placeholder commands and events from the plan** (`packages/protocol/src/commands.ts`, `events.ts`)
  - **Problem:** command types and `SwitchEvent` that nothing sends or handles; the working tune commands sit under the "Stubbed" comment.
  - **Fix:** delete them; move the tune commands up.
- [x] **11. The tuner keeps the old sample rate** (`engine/src/audio/Engine.cpp`, `setTuneMode`)
  - **Problem:** a device rate change while tuning (48 → 44.1 kHz) makes every reading ~147 cents sharp.
  - **Fix:** restart the tuner with the new rate when the device restarts.
- [x] **12. More than 8 chains in a project file share a mixer slot** (`engine/src/audio/Engine.cpp`, `applyChains`)
  - **Problem:** `slots[c.id]` gives a ninth chain slot 0, mixing it into another chain.
  - **Fix:** look the slot up with `find` and skip chains without one.
